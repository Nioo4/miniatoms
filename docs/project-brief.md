# MiniAtoms 项目简要说明

在线体验：https://miniatoms.vercel.app  
公开源码：https://github.com/Nioo4/miniatoms  
说明日期：2026-09-21

## 1. 产品定位与用户场景

MiniAtoms 是一个通过自然语言创建并持续修改小应用的 AI 工作台。用户描述需求后，可以直接操作生成的网页，再通过对话增加功能、调整样式，并保留已经录入的数据。核心价值是让用户能够持续使用和迭代自己的成果。

适合个人或小规模业务流程的原型验证：

| 用户场景 | 使用方式 | 已实测能力 |
|---|---|---|
| 求职投递管理 | 描述公司、岗位、阶段等字段，生成投递看板；使用后追加搜索、深色主题和排序 | 增删改、筛选统计、两轮追加修改、恢复旧版本后继续修改、数据保留 |
| 个人记账 | 生成收入与支出记录工具，按月份查看账目 | 新增、删除、月份筛选、收入支出结余计算、刷新持久化 |
| 习惯打卡 | 生成阅读、运动等习惯的每日记录工具 | 新增习惯、完成及撤销、统计、刷新持久化 |

这些案例通过真实模型生成，不是点击示例按钮后加载固定成品。示例按钮只帮助填写需求。新的任意需求仍可能需要调整和实际操作验证。

基本流程：免注册进入 → 新建项目并描述需求 → 查看功能计划和生成进度 → 操作预览 → 对话修改 → 查看或恢复历史版本 → 导出独立 HTML。工作台提供项目列表、对话区，以及预览、源码、版本视图和桌面／手机预览切换。

## 2. 实现思路与关键取舍

**把可靠修改作为核心。** 新代码先成为候选版本，经过结构、JavaScript/CSS 语法检查和浏览器启动检查，才通过数据库事务切换为当前版本。失败时使用实际诊断交给模型修复，最多两次；仍然失败则保留原成果。基础检查只能证明代码能通过相应检查，业务是否正确仍需实际操作。

**采用有限工具的单 Agent。** Next.js、React、TypeScript 和 Tailwind CSS 实现工作台与接口；DeepSeek 通过 `plan_app` 和 `write_app` 生成计划及 HTML、CSS、JavaScript。宿主程序控制权限、检查、超时、重试和保存，不让模型自行决定发布。一次生成通常包含规划和写码两次调用，最多四次调用；SSE 显示进度，数据库保存最终任务状态。

**将代码版本与业务数据分开。** Supabase PostgreSQL 保存项目、消息、版本、任务及应用数据，匿名身份与 RLS 隔离不同访客。生成应用通过受限的 `appStore` 接口读写自己的 JSON 数据；恢复历史版本创建新版本，只恢复代码，不回退业务数据。候选检查使用临时数据副本，避免检查过程污染正式记录。

**限制生成范围，换取可交付性。** 当前只生成原生单页前端应用，不生成任意 npm 工程或独立后端。生成代码在 sandbox iframe 中运行，CSP 限制直接网络访问；模型密钥和数据库管理凭证仅留在服务端。工作台自身具有后端和数据库。部署集中在 Vercel 与 Supabase，减少两天开发周期内的基础设施工作。

**用事务处理并发与失败。** 项目同时只允许一个活动任务，校验基础版本及数据 revision，防止旧请求覆盖新成果；恢复、取消、断线、重复反馈和额度预留都有明确处理。默认每访客每天 20 次、平台每天 100 次模型调用，按调用次数而非生成请求次数计数，失败调用也占名额。

## 3. 当前完成程度

已完成：自然语言生成、对话式修改、可交互预览、项目和对话自动保存、业务数据持久化、源码查看、历史恢复、错误修复流程、取消与超时、独立 HTML 导出、匿名访客隔离、调用额度控制，以及公开部署与源码交付。

验证分层保留证据：

- 真实 DeepSeek、远程 Supabase 和浏览器验证了看板、记账、打卡三类应用。LIVE-01～07 为同一项目连续版本链；LIVE-08～10 为另一次独立运行，产品源码和迁移相同，不声称单次全量运行通过。
- 生产站点完成独立匿名访问验收：真实生成待办应用，新增任务并勾选完成，刷新后记录和完成状态保留；共两次真实模型调用。
- `a13fde9` 的 CI 通过静态检查、构建、104 项单元测试、73 条 SQL 断言、15 项真实本地 Supabase 集成、19 项预览测试、25 项离线检查、18 项客户端测试和15项工作台测试。常规 CI 的模型为明确的测试替身，不代替真实模型验收。
- 已有约3分钟本地真实模型演示及字幕。录像演示生成、一次修改、数据保存、恢复、导出和手机视图；不是生产录屏。

尚未实现与已知限制：

- 无正式账号、跨设备找回、多用户协作或生成应用的独立分享发布。清除匿名浏览器身份后不承诺找回项目。
- 不支持 React 多文件工程、任意依赖、独立后端或外部服务集成。
- 未实现复杂数据结构的自动迁移；多标签写入冲突需要重新载入，不能自动合并。
- 启动检查不保证业务正确；iframe 没有 CPU/内存硬隔离，生成代码的无限循环仍可能影响页面。关闭页面不保证任务持续在后台执行。
- HTML 导出包含代码和本地存储适配器，从空业务数据开始，不携带平台已有记录。直接以 file: 打开时，存储能力取决于浏览器；HTTP 环境下已验证刷新持久化。

详细证据见 [验收记录](https://github.com/Nioo4/miniatoms/blob/main/docs/acceptance.md)；CI 见 [35497085287](https://github.com/Nioo4/miniatoms/actions/runs/35497085287)。

## 4. 继续投入的方向与优先级

1. **先做生成应用的分享发布。** 为通过检查的版本提供独立访问链接，明确访问权限、数据归属和发布／撤回行为。它能最快让成果被其他人使用，也能收集真实反馈；配套增加用量观测、滥用限制和错误监控。
2. **再支持 React 多文件工程和专用执行环境。** 面向更复杂的页面与组件复用，加入受控依赖安装、构建日志及更强的运行资源隔离。已有单页方案不足以承载这些能力，应在独立执行环境中实现。
3. **最后扩展带数据库和接口的全栈生成。** 明确数据模型、迁移、权限、密钥和回滚机制后，再开放服务端生成。该阶段收益高，但安全与运维成本也最高，不宜在当前版本提前铺开。

推进标准是先把一种真实场景做可靠，再扩大生成范围；每一阶段继续保留真实模型和实际浏览器验收。
